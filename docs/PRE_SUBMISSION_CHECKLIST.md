## OPEN — needs a GPU or files not in this repository

Ordered by what a reviewer hits first.

### OPEN-1 · Rerun MGCNN-SDTransformer seeds 1–4 at `--split-seed 0` — ~2 h GPU

`mgcnn_sdtransformer_seed{1,2,3,4}.json` record `split_seed == seed`. Every
other model used `split_seed = 0`. That model alone was trained and evaluated
on four different partitions, so its 66.59 ± 0.98 mixes partition variance
with training variance and its per-SNR row is computed over different test
waveforms.

This is the only outright protocol violation in the study, and the protocol is
stated as uniform in three places (`README.md` §11, `results/FINAL_RESULTS.md`
§3, `FINAL_SCIENTIFIC_AUDIT.md` Part 1). All three now carry the correction,
but the honest fix is the rerun.

```bash
for i in 1 2 3 4; do
  python scripts/run_mgcnn_sdtransformer.py \
    --seed $i --split-seed 0 \
    --out results/mgcnn_sdtransformer_seed${i}.json \
    --save-ckpt results/multiseed/mgcnn_sdtransformer_seed${i}_best.pt
done
```

Then regenerate: `scripts/reconstruct_preds.py mgcnn --seed $i --split-seed 0`,
`scripts/eval_per_class_snr.py`, `scripts/stats_tests.py`.

### OPEN-3 · Classical-branch-only ablation — ~20 min GPU

The proposed method is `fc(concat(z_deep_frozen[256], z_classical[256]))`.
There is no run isolating the classical branch, so the contribution of the
frozen deep branch is unquantified. The nearest available point is
scikit-learn's `MLPClassifier` on the same 191 features (68.15 ± 0.15), which
is a different optimiser, architecture and schedule.

Two facts make this urgent rather than optional:

* stage-2 validation peaks at epoch **0, 2, 5, 6, 15** across the five seeds —
  seed 1's selected model precedes any training at all;
* the frozen result does not track stage-1 DASNet quality once the collapsed
  seed-0 run is excluded (*r* = 0.464, *p* = 0.54).

Both are consistent with the classical branch carrying most of the load. If it
does, that is still publishable — but it must be stated, not left for a
reviewer to find. Zero `z_deep` in `DualPQNet.forward` (or pass a zeros tensor
of the same shape) and run 5 seeds.

### OPEN-4 · Original DualPQ-D with `--no-aug` and AMP disabled, 5 seeds — ~6 h GPU

The claim that *freezing* buys stability is not identified: freezing,
augmentation and mixed precision all differ between the two configurations,
and the joint run additionally trains on mismatched (waveform, feature) pairs
because `DualWaveDataset` re-noises the waveform while leaving `x_feat` at its
original SNR.

```bash
for i in 0 1 2 3 4; do
  python scripts/run_dualpq.py --gate concat --seed $i --split-seed 0 --no-aug \
    --out results/multiseed/dualpq_concat_noaug_seed${i}.json
done
```

AMP also needs disabling in `run_dualpq.py` to match `run_frozen_dualpq.py`,
which turns it off explicitly ("prevent float16 overflow in frozen weights").

This is the experiment that decides whether contribution 3 survives review.
If the gap largely disappears, the honest contribution becomes *"the
augmentation/feature mismatch in naive joint fusion is what destabilises it"*
— a better paper than the current framing, and one nobody else has written.

## Suggested framing for the draft

The evidence supports this, in this order:

1. A waveform-grouped 29-class benchmark across six noise conditions, with the
   naive-split inflation quantified (+8.07 pp) — a methodological
   contribution that stands on its own.
2. A hybrid that fuses a frozen learned time-frequency representation with
   handcrafted features and beats the strongest classical ensemble by
   **+2.44 pp macro-F1** (95% CI 1.06–3.81, *p* = 0.008).
3. **The mechanism**: the gain is entirely on the compound
   Sag/Swell + Harmonics + Flicker + OT disturbances, where handcrafted
   features saturate, at a small cost on the simple classes. This is the
   result to lead with.
4. An honest negative: at 10 dB and 0 dB nothing here beats the classical
   ensemble, and 10–11 of 29 classes are unusable at 0 dB. Reporting the floor
   is a contribution; claiming robustness that the data does not show is not.
5. Two-stage frozen training showed far lower run-to-run spread than joint
   training — reported descriptively, with the confound stated.

Avoid: "under severe noise" as a claim, "completely eliminates instability",
any per-class number quoted from `results/per_class/summary.json`, and the
seed-0 bootstrap presented as across-seed significance.
